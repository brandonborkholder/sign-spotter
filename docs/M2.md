# M2 real submission MVP

Status: implemented; awaiting one legitimate Android field submission

Build: `m2-submit-1`

## Live behavior

The deployed production PWA submits directly to PublicStuff at
`POST https://vc0.publicstuff.com/api/2.0/request_submit`. The review screen is
explicitly labeled **Live submission**, and tapping **Submit report** sends the
photo, reviewed location, stored contact information, and authenticated
PublicStuff session to Loudoun County.

The adapter reproduces the multipart contract recorded in M0:

- client `1295`, request type `1011942`, and space `40448`;
- forced-private request and the fixed **Illegal signs** issue choice;
- required contact fields and the stored disclosure preference;
- latitude, longitude, reviewed address, derived ZIP code, and JPEG attachment;
- browser-generated multipart boundary and duplicated `client_id` field; and
- response validation requiring PublicStuff's success status and request ID.

`npm run dev` remains a non-submitting development mode. Only a production build
uses the real adapter.

## Failure and recovery

- A confirmed success deletes the pending draft and displays the real request ID.
- Validation, authentication, and explicit HTTP errors retain the draft for
  correction or retry.
- A network failure or unreadable success response is marked **uncertain**
  because PublicStuff may have accepted the request. The app tells the user to
  check their PublicStuff account, retains the draft, and requires an additional
  confirmation before a potentially duplicate retry.
- An expired session directs the user to **Settings → Reconnect PublicStuff**.
- **Reset** remains available to discard the entire draft and return to camera.

## Android acceptance test

Use a legitimate sign violation. Do not submit a synthetic government report.

1. Open the installed PWA and confirm the camera starts.
2. Take a clear photograph and wait for GPS and the suggested address.
3. Verify the address, contact summary, and **Live submission** banner.
4. Keep Chrome remote debugging or another network inspector open if practical.
5. Tap **Submit report** exactly once.
6. Confirm the success screen displays a numeric PublicStuff request ID.
7. Confirm the request appears in the PublicStuff account with the correct
   photo, coordinates/address, issue type, privacy selection, and contact data.
8. Relaunch the PWA and confirm it starts at the camera rather than restoring
   the submitted draft.

If the app reports an uncertain result, inspect the PublicStuff account before
retrying.
