# M1 capture PWA

Status: implemented; awaiting Android acceptance test

Build: `m1-capture-1`

## Included

- Installable standalone PWA and **Capture sign** manifest shortcut.
- Required complainant contact profile stored in IndexedDB.
- Required PublicStuff login; password is discarded and only the returned
  `api_key` is stored locally.
- Automatic rear-camera preview with native photo-picker fallback.
- JPEG resizing to a maximum 1600 px edge at 0.82 quality.
- Concurrent high-accuracy GPS capture with accuracy warning over 100 m.
- Review, retake, GPS retry, automatic reverse geocoding, editable violation
  address, and optional note.
- Pending photo/draft recovery after a reload or app restart.
- Settings for contact edits, PublicStuff reconnection, official-form fallback,
  and local-data reset.
- Service-worker app shell and offline fallback.
- Local mock completion and explicit **M1 test mode** labeling.

## Safety boundary

The M1 production artifact does not contain `/api/2.0/request_submit` and cannot
file a complaint. It contacts PublicStuff only for the required login. The
**Finish capture test** action validates locally, deletes the pending draft, and
returns a local receipt beginning with `M1-`.

`npm run build` fails if the complaint submission endpoint appears in the
generated site.

## Android acceptance test

1. Open `https://brandonborkholder.github.io/sign-vigilante/` in Android Chrome.
2. If an older version appears, close the installed app/browser tab and reload
   once. Chrome may take a moment to activate the new service worker.
3. Complete first-time setup with the required complaint contact fields and an
   existing PublicStuff account.
4. Confirm the password field clears after login.
5. Allow camera and precise location permissions.
6. Confirm the rear-camera preview opens and the GPS chip reports an accuracy.
7. Take a photograph. Confirm it opens on the review screen.
8. Verify or edit the automatically suggested public address and enter an
   optional note.
9. Reload or close/reopen the app before finishing. Confirm the photo, GPS, and
   entered text return.
10. If GPS is missing or poor, use **Use current location again**.
11. Tap **Finish capture test** and confirm the success page says nothing was
    sent and shows a local `M1-...` receipt.
12. Capture another test using the native **Choose photo** fallback.
13. Open Settings, edit contact information, reconnect PublicStuff, and return.
14. Use **Reset all app data** and confirm onboarding appears again.
15. Install the PWA with Chrome's **Install app** / **Add to Home screen** and
    repeat launch from the home-screen icon.

Optional verification: keep Chrome DevTools Network open during the test. A
`user_login` request is expected during setup; no `request_submit` request may
appear.

## Reverse geocoding

The review screen sends the captured coordinates to the public OpenStreetMap
Nominatim service and fills the closest address it returns. The address remains
editable because the nearest mapped feature may not be the sign's actual street
address. A failed or timed-out lookup does not discard the coordinates and falls
back to manual entry. Lookups occur only after a photo is captured or the user
explicitly retries GPS; the app does not perform background or bulk queries.

## Exit

M1 is complete after the Android checklist passes. M2 will replace the local
mock gateway with the verified multipart PublicStuff adapter and retain the
official form as a fallback.
